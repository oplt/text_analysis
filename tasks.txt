# Text Research — Full Functionality Test Plan
# Manual QA checklist covering every destination under left-nav "Text Research".
# Mark each step [ ] → [x] as you verify. Prefer one fresh project/corpus for an end-to-end pass.

================================================================================
0. PREREQUISITES
================================================================================

[ ] App is running (API + frontend + workers/Redis as needed for async runs).
[ ] You can sign in (non-admin is fine for most research flows).
[ ] Have sample files ready: at least 3–10 text/PDF/DOCX docs (or a CSV for corpus import).
[ ] Ideally two user accounts (or two annotator identities) for Reliability / multi-coder checks.
[ ] Note: Celery/worker must be up for long runs (segmentation, train, topics, analysis).

--------------------------------------------------------------------------------
How to enter Text Research
--------------------------------------------------------------------------------

[ ] From the left sidebar, click **Text Research**.
[ ] If multiple projects exist, pick/open a project from the research landing (`/research`).
[ ] Confirm URL becomes `/research/<projectId>/dashboard` (or last-used research route).
[ ] Confirm page chrome shows: Research context bar, research nav groups, main workspace.
[ ] (Optional) Create a dedicated test project under **Projects** first, then open Text Research.
