# 3. REDUCE VERY LONG PAGES WITH TABS

The application currently has several pages containing many conceptually separate workflows stacked vertically.

Where content consists of distinct peer workflows, introduce page-level or section-level MUI `Tabs`.

Tabs should reduce cognitive load and vertical scrolling.

Do NOT put everything behind tabs automatically.

Use tabs when:

* a page contains multiple distinct workflows
* users normally focus on only one workflow at a time
* sections have significant vertical content
* sections represent stages, modes, result categories, or related tools
* moving content behind a tab does not hide information users need simultaneously

Do NOT use tabs when:

* users need to compare sections simultaneously
* the content is naturally sequential
* there are only two tiny sections
* an Accordion, inline section, Drawer, or progressive disclosure pattern is more appropriate

As a practical guideline, investigate pages that contain more than roughly 4–5 substantial sections or require several viewport heights of scrolling.

# 10. BALANCE WIDTHS

Audit every Grid, Stack, flexbox and CSS grid.

Eliminate awkward layouts such as:

50/50 columns where one side contains very little information

tiny controls stretched across an entire card

charts constrained into narrow columns

tables placed in unnecessarily small containers

sidebars occupying too much width

large empty right or left areas

cards whose content naturally needs different widths but receives equal fractions

Use responsive ratios based on content.

Examples:

primary / secondary:

`minmax(0, 1.6fr) minmax(280px, 0.8fr)`

workbench / inspector:

`minmax(0, 2fr) minmax(300px, 1fr)`

master / detail:

`minmax(240px, 0.7fr) minmax(0, 2fr)`

Do not mechanically use these exact values.

Choose ratios according to the actual content.

Use `minmax(0, ...)` to prevent overflow where appropriate.

---

# 11. BALANCE HEIGHTS

Do NOT give cards arbitrary fixed heights merely to make a grid symmetrical.

Instead:

* group cards with similar semantic weight
* use CSS Grid where equal-height rows genuinely improve scanning
* allow dense content to determine natural height
* keep empty/simple cards compact
* set sensible max-heights on scrollable lists
* give data tables and long result lists bounded work areas where appropriate
* avoid giant blank card bottoms
* avoid a short card sitting beside an extremely tall unrelated card when another composition would be better

For dashboard-style card rows, use consistent stretch behavior where cards belong to the same group.

For mixed-content pages, optimize visual balance rather than mathematical equality.
