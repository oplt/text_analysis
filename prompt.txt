# Definition of Done

Do not report this work as complete until all of the following are true.

### Backend correctness

* `AnalysisIdentity` works normally under Pydantic.
* Existing Python analyses remain functional.
* All research unit tests pass.
* Cache identity is engine-aware and multi-input-aware.
* Changing only keyness reference corpus B changes computation identity.
* R runtime errors remain sanitized.
* Deterministic R failures are not retried.
* Async Redis clients are never shared across event loops.
* No eager-worker operation can corrupt FastAPI Redis state.

### R worker

* actual Docker image builds;
* Celery app imports;
* worker consumes only intended R queue;
* idle worker continuously maintains readiness;
* ordinary workers cannot overwrite R readiness;
* API can detect worker disappearance;
* queued R requests require a live worker;
* worker-local R runtime validation remains in place.

### Scientific correctness

* standardized preprocessing remains shared;
* R DFM never retokenizes standardized tokens;
* DFM full matrix equality is actually verified;
* KWIC occurrence multiplicity/spans are preserved;
* dictionary document prevalence remains document-based;
* keyness tracks both scientific inputs;
* dictionary/keyness/co-occurrence parity tests remain;
* all numerical comparison tolerances are explicit.

### Reproducibility

* spec 2.0 compatibility remains stable;
* current spec identity is deterministic;
* implementation/version is server-authoritative;
* R lock contains reproducible dependency resolution;
* provenance records:

  * git SHA;
  * spec hash;
  * all scientific input checksums;
  * preprocessing identity;
  * authoritative engine version;
  * R/runtime package versions;
  * R lock checksum;

### Artifacts

# Implementation discipline

Work incrementally but continue until the entire task is complete.

After each architectural fix, run the smallest relevant test suite before proceeding.

Do not perform unrelated aesthetic refactors.

Preserve backwards compatibility for stored runs/specifications.

Where a database migration is genuinely required, create a proper Alembic migration rather than modifying old migrations.

Use immutable/content-addressed identity for scientific artifacts.

Use the existing repository abstractions for:

* artifact storage;
* object storage;
* execution;
* provenance;
* caching;
* run lifecycle.

Do not add parallel infrastructure unless the existing abstraction fundamentally cannot support the requirement.
